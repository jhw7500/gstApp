# gstApp 성능 최적화 상세 계획서 (Performance Optimization Plan)

본 문서는 i.MX8MP 플랫폼에서 `gstApp`의 CPU 사용량을 최소화하고 실시간 응답성을 높이기 위한 기술적 구현 계획을 정의합니다.

## 1. 개요
현재 `gstApp`은 기능적으로 안정적인 동기화 로직을 갖추고 있으나, 고주파 버스 메시지 처리 및 반복적인 문자열 할당으로 인해 개선의 여지가 있습니다. 본 계획은 소프트웨어 제어 오버헤드를 줄이는 데 집중합니다.

---

## 2. 상세 최적화 항목

### A. 버스 메시지 및 스레드 최적화 (main.cpp)
*   **이벤트 객체 풀링 (Object Pooling)**:
    *   `FragmentClosedEvent`를 매번 `g_new0`으로 생성하지 않고, 고정된 크기(예: 16개)의 풀을 미리 생성하여 재사용합니다.
    *   **효과**: 힙(Heap) 메모리 할당/해제 오버헤드 제거 및 메모리 단편화 방지.
*   **메시지 필터링 상단 배치**:
    *   `bus_message_parse`의 switch문 이전에 `GST_MESSAGE_ELEMENT`가 아닌 메시지 중 빈도가 높은 것들을 빠르게 `return TRUE` 처리합니다.

### B. 문자열 및 날짜 연산 최적화 (muxSinkBin.cpp)
*   **날짜 문자열 캐싱 (Timestamp Caching)**:
    *   4개 채널이 거의 동시에 `format_location`을 호출하므로, 동일한 초(Second) 내에서는 첫 번째 채널이 계산한 `date_str`과 `timestamp_str`을 전역/정적 변수에 캐싱하여 공유합니다.
    *   **효과**: 무거운 `g_date_time_format` 호출 횟수를 1/4로 절감.
*   **정적 버퍼 활용**:
    *   `g_strdup_printf` 대신 미리 할당된 `char` 배열에 `snprintf`를 사용하여 파일 경로를 생성합니다.

### C. Zero-copy 데이터 경로 재검증 (encoderBin.cpp, videoBin.cpp)
*   **픽셀 포맷 통일**:
    *   센서 출력부터 인코더 입력까지 `NV12` 또는 `I420` 포맷이 하드웨어 가속기(G2D, VPU)에서 직접 처리되는지 `caps`를 재점검합니다.
*   **dmabuf 가속 강제**:
    *   모든 큐와 변환 엘리먼트에서 `io-mode=dmabuf` 또는 `dmabuf-import` 설정을 명시하여 CPU 간섭을 0으로 만듭니다.

### D. 동기화 객체 및 I/O 최적화
*   **Mutex Hold Time 최소화**:
    *   `RecordingSession` 조회 시 데이터를 지역 변수로 복사한 후 즉시 `unlock` 하도록 임계 구역을 최소화합니다.
*   **공유 메모리 상태 관리 (Optional)**:
    *   `/tmp`에 개별 파일을 생성하는 대신, `/dev/shm` 상의 단일 파일에 비트마스크를 사용하여 프로세스 간 상태를 공유하는 방식을 검토합니다.

---

## 3. 구현 우선순위 및 난이도

| 우선순위 | 항목 | 난이도 | 기대 효과 |
| :--- | :--- | :---: | :--- |
| **1순위** | 날짜 문자열 캐싱 및 snprintf 전환 | 🟢 하 | CPU 피크 부하 유의미한 감소 |
| **2순위** | 버스 메시지 필터링 및 객체 풀링 | 🟡 중 | 장기 가동 시 메모리 안정성 향상 |
| **3순위** | Zero-copy 경로 및 큐 사이즈 튜닝 | 🔴 상 | 하드웨어 가속 효율 극대화 |

---

## 4. 성능 측정 지표 (KPI)
1.  **CPU 점유율**: `top` 기준 전체 프로세스 점유율 15% 이상 감소 목표.
2.  **지연 시간**: `splitCheck` 실행부터 실제 파일 오픈까지의 시차(Latency) 단축.
3.  **메모리**: `RSS(Resident Set Size)`의 변동폭 최소화.

---

## 5. 결론
위 계획은 `gstApp`의 로직 변경 없이 하부 구현의 효율성만을 개선하므로 리스크가 적습니다. 1순위 항목부터 순차적으로 적용하여 현장 적용성을 검증할 것을 권고합니다.
