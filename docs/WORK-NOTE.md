# Work Note: Safe Recording & Split Implementation

## 📋 최종 검토 결과 (2026-01-27 업데이트)

### ✅ 성공적으로 구현 및 수정된 항목

#### 1. GStreamer 앱 (`gstApp`)
- **[구조 개선]** `.part` 확장자로 임시 파일 생성 로직 통일 (`format_location`).
- **[호환성 해결]** GStreamer 1.18.0에서 존재하지 않는 `fragment-closed` 시그널 대신 **GstBus 메시지(`splitmuxsink-fragment-closed`)**를 사용하여 세션 완료 감지 성공.
- **[세션 동기화]** 파일명에서 `YYYYMMDD_HHMM` (분 단위)까지만 추출하여 모든 채널을 하나의 세션 ID로 그룹화하는 로직 최적화.
- **[동적 감지]** `cmdArg.cam[i].enable` 설정을 참조하여 활성 채널 수를 자동으로 계산, 모든 채널이 완료되었을 때만 `/tmp/session_*.all_done` 생성.
- **[안정성]** `splitmuxsink`에 `send-keyframe-requests` 및 `message-forward` 속성을 활성화하여 정확한 시점에 파일이 분할되도록 유도.

#### 2. 메타데이터 엔진 (`vcm`)
- **[로직 일치]** 자막 파일 생성 시 영상과 동일하게 `.srt.part` 확장자를 사용하도록 수정 (`tcpServer.cpp`).
- **[처리 시점]** 영상 파일의 완료 시그널과 동기화되어 `chk_cam_operate.sh`에 의해 한꺼번에 처리되도록 연동.

#### 3. 모니터링 데몬 (`chk_cam_operate.sh`)
- **[경로 보정]** `final_path`가 상대 경로로 들어올 경우 발생하던 이동 오류 해결 (자동으로 절대 경로 `/` 추가).
- **[통합 처리]** `ProcessFile()` 함수 하나로 `.mp4.part`와 `.srt.part`를 모두 처리하도록 일반화.
- **[로그 강화]** `mv` 명령 실패 시 `/dev/null`로 버리지 않고 상세 에러 메시지를 로그에 기록하도록 수정.
- **[정리 로직]** 10분 이상 방치된 `*.part` 파일들을 영상/자막 구분 없이 자동으로 삭제하여 디스크 공간 확보.

### ⚠️ 미완료 또는 추가 검토 필요한 항목 (Technical Debt)

**1. GStreamer 핸들러 경량화 (Work Queue 도입)** (우선순위: 중간)
*   **현황**: 파일 생성(`fopen`) 및 뮤텍스 로직이 메인 루프(Bus Watch) 안에서 동기적으로 실행됨.
*   **위험**: 파일 시스템 I/O 지연 발생 시 Pipeline 전체가 순간적으로 멈칫할(Blocking) 위험 존재.
*   **권장**: 고부하 환경 대비 별도 스레드(Work Queue)로 I/O 로직 분리 필요.

**2. 에러 처리 강화 (SD 카드 Full/Recycle)** (우선순위: 중간)
*   **현황**: `CheckDiskSpace`가 로그만 남기는 수동적 감시 상태.
*   **권장**: 디스크가 꽉 찼을 때 가장 오래된 파일을 삭제하거나 녹화를 안전하게 중단하는 능동적 방어 로직 구현 필요.

**3. NTP 시간 변경 대응** (우선순위: 중간)
*   **현황**: `CleanupStaleFiles`가 시스템 시간(`date +%s`)에 의존.
*   **위험**: 부팅 후 NTP 동기화로 시간이 크게 변경될 경우, 방금 녹화한 파일을 오래된 파일로 오인하여 삭제할 수 있음.
*   **권장**: Monotonic Clock 사용 또는 시간 변경 이벤트 감지 로직 추가.

### 🔍 파일시스템 안정성 검증 결과

- **전원 차단 시나리오**:
  - 녹화 중인 파일은 `.part` 상태로 남음 → 재부팅 시 마운트 스크립트나 `CleanupStaleFiles`가 자동 정리.
  - 완료된 세션은 `all_done` 마커 확인 후 이동되므로 깨진 파일이 최종 폴더에 남지 않음.
- **파일 무결성**:
  - `mv` 전후의 **3단계 sync(Source File -> Source Dir -> Target File)**를 통해 메타데이터와 실제 데이터가 디스크에 완전히 기록됨을 보장.
