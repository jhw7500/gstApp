# 채널 시작 진단 이력 문서 정리 설계

## 목적

미추적 상태인 `docs/gstapp-handoff-2026-08-11-channel-logging.md`는
수정 전 장애 현상의 원시 로그와 `gstApp`/`pim-package-jhw` 연계 이력을
담고 있어 보존 가치가 있다. 그러나 현재 동작처럼 서술한 내용과 이미 완료된
개선 제안이 섞여 있으므로 그대로 Git에 추가하지 않는다.

이 작업은 해당 파일을 현재 운용 지침이 아닌 **수정 전 장애 이력**으로
변환하여 추적하고, 기존 검증 문서가 새 이력 문서를 가리키도록 정리한다.

## 범위

1. 미추적 handoff를
   `docs/CHANNEL_STARTUP_DIAGNOSTICS_HISTORY.md`로 이름을 바꿔 추적한다.
2. 문서의 기준 시점, 해결 커밋과 병합 커밋을 명시한다.
3. 당시 관측 사실과 해석을 분리한다.
4. 이미 구현된 제안을 현재 구현 결과로 바꾼다.
5. 오래된 작업 트리 경고, 개발자별 절대 경로와 잘못된 배포 경로를 제거한다.
6. `docs/PR38_REVIEW_FOLLOWUP_VALIDATION_20260814.md`의 미추적 문서 보존
   설명을 새 추적 문서 참조로 갱신한다.

`.jhw/`, `.superpowers/`의 실행 산출물과 `tmp/` 로그는 생성·중복 자료이므로
새로 추적하지 않는다. 제품 코드, 설정, 빌드 파일과 타깃 상태는 변경하지 않는다.

## 문서 구성

정리된 이력 문서는 다음 순서로 작성한다.

1. 문서 성격과 현재 상태
2. 당시 시험 환경과 수정 전 기준점
3. 보존할 원시 관측 내용
4. 관측 사실과 당시 해석의 구분
5. 확인된 수정 전 진단 공백
6. `gstApp`에서 구현된 결과와 커밋 근거
7. `pim-package-jhw`에 반영된 결과와 커밋 근거
8. 현재 확인 방법과 남은 한계

현재 사실은 함수와 파일 위치로 확인하고, 과거 상태는 고정된 Git SHA를
근거로 기록한다. 원래 현상을 수정 후 같은 조건에서 재현·해소한 원시 증거가
없으면 이를 명시하며, GStreamer bus 오류가 없었다는 사실만으로 하드웨어나
드라이버 오류가 없었다고 단정하지 않는다.

## 정확성 기준

- 수정 전 기준점: `29bf631`
- `gstApp` 해결 커밋: `7977cda`, `3596edc`
- 병합된 현재 기준점: `69db31a`
- `pim-package-jhw` 관련 커밋: `7b2a112`, `7802a08`, `6e28828`, `63d8484`
- 배포 경로는 `update_bin.sh`의 현재 대상인
  `pim-package-jhw/dist/pim/usr/local/bin/gstApp`로 기록한다.
- 비밀번호, 토큰, 개인별 절대 checkout 경로는 문서에 포함하지 않는다.

## 검증과 종료 조건

- 모든 커밋 SHA가 각 저장소에 존재하고 역할 설명과 일치하는지 확인한다.
- 현재 구현 설명을 `main.cpp`, `encoderBin.cpp`, `muxSinkBin.cpp`와 대조한다.
- 이전 파일명, 완료되지 않은 제안 표현, 오래된 dirty-worktree 경고와 잘못된
  배포 경로가 남지 않았는지 검색한다.
- 자격 증명 패턴과 개인별 절대 경로가 없는지 확인한다.
- `git diff --check`를 통과하고 변경 범위가 문서에만 한정되는지 확인한다.
- 독립 읽기 전용 리뷰에서 중요한 정확성 문제가 없을 때 완료한다.
